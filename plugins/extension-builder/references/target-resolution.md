# 目标与文档路径解析

任何路径解释、任务恢复、首次写入或委派前读取。Main 负责解析，developer 和 reviewer 接收绝对路径，不根据自己的 cwd、worktree 或配置重新计算。

## 三种根目录分开

- **Builder 资源根**：当前已加载插件的资源位置，只用于读取指引、模板与脚本。不能将其安装绝对路径嵌入生成产物。
- **目标源码根**：用户要维护的组件或插件位置，控制目标 SKILL、Agent、README、代码和配置；必须独立批准。
- **过程文档根**：设计、决策、快照、评审与测试证据的位置，由本协议确定。它不改变源码、catalog 或 README 的位置，不赋予对其它文件的读写权。

## 组件目标识别

优先使用显式目标，其次使用已确认上下文，再看工作区相关结构；仍有歧义则问。区分项目根、`.claude/`、`skills/` 集合、单个 Skill 目录、单文件、插件源码根。给出现有文件就维护原件，不复制、不重复追加 `.claude/skills`。

未指定目标时，项目 Skill 的候选是 `<确认工作目录>/.claude/skills/<name>/`、项目 Agent 候选是 `<确认工作目录>/.claude/agents/<name>.md`；只是供确认的候选，不能覆盖用户明确要求的作用域。用户级或插件级必须按适用宿主规则核实。自定义源码路径不等于已被宿主发现，保存与加载分别说明。

写入前读取现状，检查同名遮蔽、用户修改、调用方、真实路径和符号链接。共享配置只改获准条目。安装缓存与源码分别识别，不擅自修改可替换缓存。路径越界或归属不明先返回 Main 确认。

## 取得配置与优先级

入口 Skill 把 `${user_config.docs_base_dir}` 提供给 Main。只读这个非敏感值，不扫描用户配置或凭证。原生配置声明的默认值是 `documents`。

新任务优先级：**用户当次显式文档 base > 有效配置 > 明确未设置时的内建默认 documents**。但空字符串、全空白、无效格式或原样未解析占位符都属于配置问题，不等于“未设置”。不能静默回落 cwd 或默认目录。显式有效路径可覆盖无效配置，记录来源；仍需报告发现的配置问题而不修改宿主设置。

用户指定的是已有设计文件或完整 task 目录时，保留该具体目标，不再追加后缀。无法判断用户说的是 base 还是完整 task 目录时询问。

原生非敏感 `pluginConfigs` 作用域是 user/managed；不要指导用户在项目或 local 设置中覆盖，也不新增自定义项目配置机制。只有实际宿主取值验证才能证明选项已生效。

## 固定基准并生成任务目录

1. **区分新建与续作**。续作先读可信记录，沿用既有绝对目录。新任务固定 `workspace_anchor` 为开始时确认的工作目录；不是自动猜的 Git 根、组件根、插件安装根或 SubAgent 目录。用户要求会话最初启动目录而无法可靠确定时先问。
2. **按目标平台解释路径**：`documents`、`./documents` 相对 anchor；绝对路径保持绝对；`~/...` 明确展开当前用户主目录。其它变量、`~other`、命令替换或用户展开表达式首版不隐式执行/展开，要求明确路径。合法空格保留，不按空格拆参。平台路径格式不明时询问。
3. **对照项目约定**。文档约定冲突时确认，不能静默覆盖。记录原始值、来源、anchor 和解析后的绝对 base。
4. **新任务追加单层标识**：`<base>/extension-builder/<component-builder 或 plugin-builder>/<task-id>/`。插件后缀是本 Builder 名称，不是目标插件名。`task-id` 应唯一，例如经存在性检查的任务短名加随机标识；时间戳单独使用不能保证唯一。每个后缀仅允许字母、数字、连字符、下划线构成的单层名称；禁止 `/`、`\`、`.`、`..`、空值、控制字符及路径穿越。不清洗恶意标识后静默接受，直接要求更换。
5. **核查真实位置与碰撞**。检查已有祖先和符号链接，按文件系统语义先解析链接再处理 `..`，不要词法折叠掩盖越界。绝对 base 可在工作区外，但先展示真实 base 并获准；所有追加后缀解析后必须仍在获准真实 base 下。新任务目标已存在就停止，辨别续作还是另选唯一 ID，不覆盖内容。目标为已有文件则核对文件身份和所在任务目录。
6. **展示并批准**。展示最终绝对 `task_dir`（已有文件同时列文件路径）、预期用途和写入范围，将其纳入留档批准。缺权限时返回 Main，不扩大权限。配置偏好、目录可写、用户选择某模型均不能产生留档授权。
7. **写入前再核查**。目录、链接或内容变化时暂停并重新核验，不能靠旧检查覆盖并发变化。路径值只作为数据传递；不得直接插入 shell 字符串执行，使用安全参数传递，不运行配置中的表达式。
8. **交接**。Main 将绝对 `task_dir`、批准快照和获准证据位置传给 developer；reviewer 只接收需读取的绝对文件路径，返回 findings，由 Main 留档。

这是一套执行协议，不是随包附带的文件系统沙箱或通用路径验证程序。静态文本检查不能证明这些路径行为已运行通过。

## 续作与存储边界

- 当前任务开始后不因 `cd`、worktree、会话、入口或配置改变而重算。新配置只影响之后的新任务。
- 续作沿用已有 `workspace_anchor` 和绝对 `task_dir`，核对实际文件与批准依据；不再次拼接后缀、不自动迁移历史记录。
- 跨机器原路径失效时请求新位置；文档迁移单独确认源、目标、冲突、引用更新和删除范围。
- 用户过程文档不以插件安装目录或 `CLAUDE_PLUGIN_DATA` 为唯一存储位置；插件内部缓存的卸载生命周期不能作为用户文档保留保证。
- 一次有效的 task 目录授权可供范围内后续留档复用，不为每份报告重复确认。超出目录、用途或数据范围仍要确认。
- 过程文档和证据不自动提交或公开；秘密、个人数据和敏感日志不进入报告。

配置事实依据见 [manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md) 与 [settings reference](https://code.claude.com/docs/en/settings-reference.md)。具体宿主取值和路径行为按任务验证，不能以链接存在代替验证。
