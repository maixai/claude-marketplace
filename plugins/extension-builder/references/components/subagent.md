# SubAgent

确需独立上下文、独立检查或不同工具边界时读取；不要仅为每一步配一个角色。

## 设计输入

明确职责、调用者、完整输入、返回契约、允许读取/修改范围、工具、模型、停止条件和不可用处理。独立上下文不会自动继承主会话；必须自包含交接，不用“按上文”替代任务包。

模型按用户选择声明，不静默切换或以高档位代替测试。实际模型路由与配置别名分开记录。提示词中只读不是技术边界，工具用显式最小清单；Bash 不是文件级沙箱。

## 实施与限制

按 [SubAgents](https://code.claude.com/docs/en/sub-agents.md) 和 [插件组件](https://code.claude.com/docs/en/plugins/components.md) 核对作用域与版本。插件 Agent 不依赖会被忽略的 `permissionMode`、`hooks`、`mcpServers` 建立权限或服务。需要服务由 Main 确认实际宿主环境，不给角色虚构能力。

只读 reviewer 直接返回 findings，由 Main 获准后留档；不要求没有 Write 的角色写文件。需要浏览器、时钟、执行或额外检索但没有工具时返回 Main，不能通过替代途径绕过限制。

独立评审使用新上下文、不给作者自评与其它 reviewer 结论。不要默认嵌套委派；若目标确需编排，必须作为新增机制讨论，而不是在说明里暗加 Agent/Workflow 工具。

## 验证

- 静态核对非空 description、声明工具、模型、资源引用与输入输出是否自洽。
- 在获准独立会话确认实际注册名称、可见工具和模型可用性，不以文件存在当已加载。
- 用缺历史、缺输入、范围变化、工具缺失和返回阻塞的用例验证交接。
- 检查真实工具轨迹与文件差异；只读角色不写、不执行；能力不足如实回 Main。
- 缺角色加载或路由证据则单列未验证，不用普通角色冒充目标类型。
