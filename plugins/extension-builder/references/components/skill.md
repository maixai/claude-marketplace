# Skill 与旧 Command

设计或维护可复用任务指引时读取。只需一次操作且无复用需求时，不为凑组件创建 Skill。

## 设计与实施

1. 从成功与失败示例明确触发、不触发、输入输出、人工批准和退出条件；description 应足以选择入口，正文不能只重复简介。
2. 先读现有文件、直接引用资源和调用方。区分用户级、项目级、插件级和自定义源码，确认最终路径与宿主发现方式；不重复拼接 skills，不擅自复制现有组件。
3. 按 [Skills 官方资料](https://code.claude.com/docs/en/skills.md) 核对目标版本的 frontmatter、变量、调用和上下文行为。通用 Agent Skills 与 Claude Code 扩展不混用；不确定字段先取证。
4. 主文保留可执行流程与关键边界，长知识按需拆引用；引用注明何时读取。模板用于稳定输出，脚本只做确定性重复操作，不替代未决业务判断。
5. 用户交互、澄清和批准留主会话。需要隔离时显式委派窄任务，不把完整交互入口机械 fork。工具授权应最小，不以宽泛 allowed-tools 自动预授权。
6. 辅助 Agent、Hook 或新依赖仅在必要且已批准时创建；不要求每个 Skill 都有脚本和团队。

维护旧 Command 时先核对原调用名、参数与加载规则，保留兼容。新组件可优先考虑 Skill，但不默认把既有 Command 迁移或删除。

## 验证与交付

- [有限结构检查](../validation.md) 验证文件、分隔与部分引用，保留 YAML/语义 unverified。
- 宿主实际调用确认命中目标版本和命名空间，不测试同名旧副本。
- 行为用例覆盖正向触发、普通任务排除、缺输入、只讨论不写、失败、批准与续作。维护增加旧版本保留用例。
- 检查生成目标保留其需要的变量表达式，而非误用 Builder 安装路径；安装副本不得依赖包外旧资源。
- 真实评测前批准模型与预算。静态规则存在和文件生成都不能证明交互门禁已通过。

产出为最小 Skill 及获准配套资源、保存/加载说明、验证证据和未知项，不默认安装或发布。
