# Monitor

适用于明确需要长驻进程和持续状态输出的任务；一次命令或交互 Skill 能解决时不新增常驻机制。Builder 自身不启动 Monitor。

## 设计前确认

明确启动条件、命令和 cwd、环境依赖、输出协议、ready/错误信号、进程生命周期、重启策略、资源上限、用户交互、停止与清理。外部访问、数据范围、费用和真实启用分别批准，不把编写文件当启动许可。

按 [插件组件](https://code.claude.com/docs/en/plugins/components.md) 当前 Monitor 章节核对宿主与作用域的支持、发现位置、配置和生命周期。没有可用宿主或资料时保留未知，不根据其它组件的字段拼 schema。

## 实施与维护

先读待执行代码与既有接入。路径、环境参数和用户输入按数据处理，避免 shell 插值。定义失败时对主会话的影响，不用无限重试掩盖错误。只管理本任务创建的进程，避免杀掉同名的其它进程。迁移时保留原启动/输出/清理契约，变更行为先确认。

## 验收与限制

在获准真实交互宿主验证启动、准备就绪、更新、用户交互、异常退出、停止、恢复与清理；记录进程身份和原始输出。非交互 eval、脚本通过或文件存在不能证明交互运行有效。工具不足交 Main，不绕过连接/权限。

maixai 现有采集器不完整覆盖 Monitor。若 plugin-builder 目标包含它，必须提出展示扩展并获准，或记录用户明确接受的展示限制；不能漏项后称完整交付。
