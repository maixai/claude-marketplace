# LSP 接入

仅在需要语言诊断或导航能力时添加。Builder 的 developer 可以使用已提供的 LSP，但不自动安装语言服务。

## 方案与实现

确认语言、目标宿主/版本/作用域、服务二进制及版本前提、启动命令与 cwd、文件扩展映射、配置、资源消耗、启动失败及关闭方式。按 [插件组件](https://code.claude.com/docs/en/plugins/components.md) 的 LSP 部分核对准确字段，不能从其它 server 配置类推。

先读取现有服务与调用方，保护其它语言映射。外部依赖不存在时说明阻塞并请求安装授权，不自行下载。生成路径可移植，不写维护者本机二进制或 Builder 缓存绝对路径。

## 分层验证

1. 检查配置结构和二进制前提，未执行就不宣称可用。
2. 获准启动后确认宿主实际连接目标服务、打开正确工作区。
3. 用安全夹具分别验证诊断、跳转或任务要求的能力，并检查未知语言/服务退出路径。
4. 诊断与实际构建/测试冲突时保留两类证据，确认索引是否更新，不凭单一静态错误删改正确代码。
5. 按批准范围清理测试进程；缺运行环境则列未验证。

maixai 网站读取 `.lsp.json` 根映射的名称，不要求非官方 description。自定义路径或内联声明先核对采集能力，不自动扩展全站。
