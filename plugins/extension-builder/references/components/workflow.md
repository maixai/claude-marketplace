# Workflow

仅在用户明确需要可重复编排、分支或恢复时考虑；Builder 本身不是通用编排平台，不为普通任务默认引入 Workflow。

## 先区分目标

确认用户指的是 Claude Code 的 Workflow 工具/扩展、普通步骤说明，还是其它产品工作流。不要把产品之间的 API 或权限混用。定义输入输出、依赖图、分支、失败重试、幂等、恢复点、并发写入责任、成本上限和停止条件。

编写脚本不等于获准运行。运行、外部访问、模型费用、持久状态和副作用必须明确。发现原方案用一个 Skill 足够时提出简化，不把复杂机制作为必选。

## 实施

先读取当前宿主可用的官方 Workflow authoring 指引/工具契约与目标版本证据；未提供 API 时回 Main 获取，不能凭记忆发明方法或参数。若宿主提供专用 authoring skill，按宿主规则加载；当前角色没有 Skill 或 Workflow 工具则回 Main，不绕过白名单。

明确数据与指令边界，按获准范围读写；每个步骤输出足以支撑后续步骤，失败不自动提升权限。避免同一文件多个写入者，不递归派生无界团队，不把恢复记录当用户批准。

## 验证与展示

先对可离线检查的结构与输入输出做确定性验证；真实运行另获批准，覆盖成功、分支失败、中断恢复、重复执行和预算停止。记录实际状态与清理，非交互片段不证明完整交互链。

maixai 当前采集器不完整覆盖 Workflow。先提出最小展示扩展范围并获准，或明确记录用户接受的缺口，不能把宿主能运行当网站已展示。
