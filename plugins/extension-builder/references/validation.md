# 验证与证据协议

制定验收、运行检查、交接实现评审和最终交付时读取。Builder 行为、生成产物、实际宿主/website 是三种测试对象，不能互相替代。

## 分层验收

1. **静态结构**：文件、元数据、frontmatter、可识别引用、模型/工具字段、范围和变量。证明所检查的结构，不证明完整 YAML/schema 或行为。
2. **宿主发现与加载**：在获准环境确认加载的是目标版本和命名空间，不是同名副本。只读新文件并模仿不算真实加载。
3. **真实行为与失败分支**：逐阶段输入批准，观察工具调用和文件变化。只讨论不写、需求不清先问、有效批准继续、缺工具停下等必须有真实执行证据。
4. **回归与独立评审**：检查保留契约、实际 diff、范围与证据；reviewer 的静态 pass 不代替缺失运行测试。
5. **插件网站**：plugin-builder 另走 [网站验收](../skills/plugin-builder/references/website-validation.md)，构建与采集成功不代替浏览器。

每项明确通过、失败、未验证、阻塞或不适用；未执行的行为用例不得因规则写在文件里而标通过。

## 运行前边界

先读脚本/Hook，再执行获准检查。不自动安装依赖、启用 MCP、修改宿主权限或加载整个市场。受控加载只加载目标插件和必要依赖；记录并清理获准测试进程、临时配置和工作区，不动范围外进程。

实际模型评测另确认场景、方式、隔离、凭证来源、模型、预算与停止条件。遵循目标项目凭证规则，隔离 HOME，不复用个人秘密配置，不打印令牌。无预算许可就只写用例，不发真实请求。配置别名与可观察实际模型分别记录，不可观测则写未知。

UI、网络或交互验收遵循目标项目 Chrome DevTools 规则。developer 白名单没有 Chrome 工具，交回 Main；不可用则未验证/阻塞，不绕过拒绝连接。非交互 eval 不证明 Monitor 交互或完整多轮批准。

## 有限结构脚本

[validate_skill_structure.py](../scripts/validate_skill_structure.py) 从旧 Skill 检查器迁移，仅用于一个 Skill 目录与显式配套文件，不是通用插件校验器。Python 标准库，无额外依赖；不联网、不写目标、不执行夹具代码、不解析 YAML。

先确定 Builder 资源根与目标根，以下是需要替换绝对路径的模板；每个额外根必须已经获准：

```bash
python3 -I /ABS/BUILDER/scripts/validate_skill_structure.py \
  --skill-dir /ABS/TARGET-SKILL \
  --agent /ABS/APPROVED-AGENTS/helper.md \
  --component /ABS/APPROVED-HELPERS/check.py \
  --allow-root /ABS/APPROVED-SHARED-RESOURCES
```

- `--skill-dir` 递归扫描；目录符号链接不递归进入。
- `--component` 只允许和检查该精确文件；`--agent` 同时要求 frontmatter 分隔；都不自动批准其父目录。
- `--allow-root` 允许核查该根内引用，不自动扫描整个根。本插件两入口引用共享资源位于 Skill 外，检查时必须显式允许相应插件根或共享根，不能隐式放宽。
- 检查存在性、空文件、UTF-8、frontmatter 分隔和有限 Markdown 文件引用。CLI 的四类路径参数与文件引用都保留 `link/..` 分量，先按文件系统语义解析再判范围；相对参数只添加调用 cwd，不先词法折叠后换成另一检查对象。
- 根目录的真实位置若与词法位置不同，报告 scope fail，不自动批准符号链接目标，也不把词法位置当作替代授权根。精确配套文件同样不能暗中批准另一位置；其真实目标必须已在其它明确获准范围内，或由用户直接提供并批准真实路径。没有语义差异的普通 `..` 和范围内链接父目录路径仍可检查。
- 不解析 YAML 字段或类型、不验证完整 Markdown、锚点、动态引用、宿主语义或权限。外部 URL 不抓取。未知二进制与超过 1 MiB 的文本不读为通过。
- JSON 含逐项 `pass/fail/unverified`。退出码 `1` 为发现失败；`2` 为无失败但有未验证；`0` 仅表示所列检查通过。argparse 参数错误也退出 `2`，但没有有效结果 JSON，必须分别处理。
- `fail` 优先于 `unverified`。正常 Skill 包含 YAML/运行语义未覆盖，所以总体 `unverified` 是有意义的结果，不为变绿删除提示。

本插件确定性单测使用标准库。命令模板在任意目录执行，替换根路径：

```bash
python3 -I -B -m unittest discover -s /ABS/BUILDER/tests -p 'test_*.py' -v
```

## 状态绑定与有效证据

发起实现评审前记录：diff 基线、相关文件清单与待评审状态、每项测试执行命令/环境/原始结果、该项所测试的产物身份。干净已提交文件可用提交；未提交、未跟踪或仓库外文件必须有文件内容标识，不能只用 HEAD。

检查和评审期间不并发改相关产物。状态漂移或证据无法对应时，旧结论不能作为当前通过证据。测试后修改文件要重跑受影响检查，并让 reviewer 复核受影响项；无影响检查可说明依赖与理由后复用，不确定时扩大回归。

历史结果保留原身份，不改成新结果。最终交付绑定最终文件和仍有效证据。没有必要就保留原始输出在会话；获准持久留档时写指定 evidence 位置，不另建状态系统。

## 用例应能抓错

[行为规格](../tests/scenarios.md) 覆盖入口、批准、交接、目录、维护和失败路径。[evals 说明](../evals/README.md) 描述少量可加载用例；只存在文件不意味着运行过。

确定性 grader 检查工具和新文件；语义 grader 检查回答与决策。禁止写入的负例应让被测流程具有写入能力才有判别力，不能把权限拦截当主动守门。只检查回答“不修改”不足以证明无修改；比较文件差异和调用轨迹。后续批准不能提前泄露给负例。已有文件变更不能只靠“未新建文件”判定。
