# 委派、评审与留档

派发任何共享角色、冻结方案、保存评审或恢复任务时读取。Main 负责交互与授权；角色使用专用类型的新上下文，不 conversation fork，不预加载两个完整入口，不嵌套委派。

## 角色与任务包

少量调研由 Main 做；复杂实施默认交 developer。独立设计与实现评审分别交对应 reviewer，不能用开发者自评替代。宿主若未加载目标角色或模型不可用，按 [生命周期](lifecycle.md) 报告，不冒充调用成功。

向 `extension-builder:builder-developer` 提供自包含任务包：

- 用户目标、非目标、成功标准与必须保留的行为。
- 最终批准的设计修订、稳定快照绝对路径及内容标识；可信用户批准摘要和未决项。
- 源码、允许文件/配置项、禁止范围、已有用户改动与基线。
- 适用规则、按需组件指引、市场事实和官方证据路径。
- 可执行检查、网络、激活、费用预算、停止及清理要求；未授权事项明列。
- Main 已解析的绝对 `task_dir`、允许写证据的位置与输出契约。未获留档许可时只返回结果。

准确引用资料，保留关键限制，但不复制全部源码。不能写“按上面做”就假设新上下文知道历史。developer 不重新解析配置或 cwd，不替用户批准，不调用其它角色。拥有 Bash 也不等于文件级隔离；不通过 CLI/SDK 绕过工具限制。需要浏览器而工具未提供时返回 Main。

同一任务范围内修订优先续用原 developer；授权变化先更新任务包。不同目标不得沿用过时批准。不默认 worktree，先分析跨仓库、用户级组件、用户改动和环境。共享文件和页面只有一个写入/操作负责人，Main 不同时重做委派工作。

## 独立设计评审

交给 `extension-builder:builder-design-reviewer`：用户原始需求与澄清、已决偏好和非目标、明确身份的完整设计快照、宿主/作用域、仓库事实、关键官方证据、未决与焦点。

首轮不注入作者自评、辩护或其它 reviewer 结论。评审以需求与事实为基准，不把被评方案当成正确前提。人工 review 可以并行，但双方必须审同一快照。Main 继续维护工作稿时不能让 reviewer 读取变化中的版本。

检查需求覆盖、事实适用性、职责与上下文、权限副作用、兼容、成本失败处理、验收有效性。必须构造“实现错误但测试仍通过”的反例，不只确认写了测试计划。

每条 finding：ID、严重级（blocking/substantive/advisory）、位置、问题、触发条件或反例、证据、影响、最小修正方向、是否需用户决定。证据缺口与已证缺陷分开，“没查到”不能写成“不支持”。总体用“未发现设计层面阻塞/需要修订/材料不足”，不能写“已批准实施”。

架构、权限、范围或关键验收改变时复核受影响部分；复核可读相关旧 finding、处置、diff 与新证据。纯措辞不机械重审。没有新证据的同一争议停止自动循环。

## 独立实现评审

向 `extension-builder:builder-reviewer` 提供用户需求、最终批准设计、允许范围、真实 diff 与基线、待评审文件内容标识、逐项原始测试结果及对应状态、未验证清单和适用规则。reviewer 直接读实际产物，不只读 developer 摘要，不读作者自评或其它评审结论。

返回 `pass/changes-requested/blocked`、范围、带位置和反例的 findings、证据缺口、未评审部分。必要测试缺失不能靠静态阅读给整体验收 pass；只能明确报告有限范围结果及整体阻塞。只读 reviewer 不执行测试或计算命令；Main 提供原始结果和状态标识。状态不明则请求材料，而非猜测。

## 文档身份与持久化

- 复杂方案的工作稿与交接快照分开。快照只在 review、批准、实施交接需要稳定对象时建立，不为每句话复制文件。
- 方案修订号与快照内容标识绑定；已提交文件可用固定提交内容，未提交文件不能只用 HEAD。用户直接修订时保护并发修改。
- reviewer 返回的报告明确绑定所读修订与快照。D1 报告不自动覆盖 D2；批准旧版也不能覆盖改变范围/权限/行为的新版。
- 实施只使用最终批准快照。源码漂移时重新核对适用性。原始 diff、逐项测试、实现评审均按 [验证协议](validation.md) 绑定实际产物。
- 两类 reviewer 默认只读、直接返回。Main 在获准 `task_dir` 保存**原始 findings**，不改写问题、证据、严重级；接受/拒绝/修订/用户决定另写处置记录。新轮次追加，不覆盖旧记录。
- 已返回内容无需为了留档再读取一遍。短任务无留档许可时仅保留会话；报告过长需另设输出方式时，先确认权限和契约，不能要求只读 reviewer 写文件。
- 文档是依据，不是授权令牌。恢复时核对真实用户批准、设计身份、实际文件和绝对 task 路径；只有 approved 状态不足以继续实施。

Main 交付时说明完成、部分完成或阻塞，列出有效证据和未验证项，不重复贴全部源码或成功日志。
