# 维护、迁移与自举

修改、升级、迁移、删除或自维护前读取；与 [生命周期](lifecycle.md) 的批准规则共同执行。

## 修改前建立保留契约

读取目标、直接资源、调用方、接入配置和现有测试，列明“改变什么/不改变什么”：触发与名称、输入输出、权限与失败处理、模型、用户配置和数据、对外调用及网站地址。检查未提交和未跟踪文件，保护用户修改。

默认最小 diff，不按新模板整套重生旧组件。写入前再次对照现状；发现并发修改、与设计基线不符或范围外依赖时暂停，交 Main 裁定。回退只撤销本次可识别改动，不重置整个目录。

共享配置只改负责的条目，不覆盖其它键。配置写入、实际应用和加载可能有不同副作用，必须在批准中分别说明。新增权限不能作为“修复细节”直接添加。

## 升级与名称迁移

源码维护、发布准备、实际发布分开。日常编辑不默认 bump 版本；发布时按真实对外契约及项目策略判断，不机械把触发词变化或依赖升级都判 major。

保留已发布技术标识；确需更名时分析安装身份、调用名称、配置键、数据位置、市场条目与旧网页 URL。先决定兼容策略，不假定市场 renames 会修复 website 路由。目标无持久数据就不新建迁移框架；有真实数据才明确备份、幂等、重试、回退和验证授权。

用户显式给出现有文件时维护原件；迁移位置先确认源、目标、冲突和引用更新。文档配置变化不自动迁移历史记录。

## 源码、安装与运行

核实真实来源与路径，不能仅凭“已安装”断定是缓存。有些本地市场相对路径插件原地加载，另一些来源使用缓存，按实际 [加载规则](https://code.claude.com/docs/en/plugins/loading.md) 核实。

默认维护用户指定源码，不编辑可替换安装缓存。自定义源码尚未加载就明确说明；安装、刷新/新会话、激活与卸载分别需授权。验证时确认实际命中对象，避免同名遮蔽导致测试另一份组件。

## Builder 自维护

本任务继续使用已加载的稳定指引，新源码在另一个获准会话验证。不在同一任务无提示切换规则，也不把“读取新文件并模仿执行”当成宿主真实加载。

旧 skill-author 和其它旧工具保留用于自举对照；切换、安装和删除旧副本另行批准。本插件运行资源全部留在包内，不依赖旧工具目录。新四角色尚未加载时，不用普通角色冒称它们已生效。

修改后重跑受影响检查并更新产物内容标识；历史结果保留其适用版本，不能改标题复用为新版通过证据。详见 [验证协议](validation.md)。
