# 固定目录与恢复

Main 解析并传递路径。角色只用交接中的绝对路径，不从自己的 cwd、worktree、插件缓存或配置重新计算。

## 新任务

1. 固定用户确认的起始工作目录 `workspace_anchor`，独立确认源码根与允许写入范围。
2. 文档 base 优先使用用户本次明确指定的 base，其次是原生 `${user_config.docs_base_dir}`；只有明确未设置才使用内建默认 `documents`。空白、未替换占位符、无效格式不能静默回落。显式路径可以覆盖无效配置，但仍报告配置问题，不改宿主设置。
3. 相对 base 相对 anchor 解析；绝对路径保留；`~/` 明确展开当前用户主目录。其他变量、`~other`、命令替换等不隐式执行或展开。路径中的空格作为数据保留。
4. 新任务目录为 `<base>/maixdev/fastdev/<task-id>/`；task-id 是经存在性检查的单层字母/数字/连字符/下划线标识。禁止空值、`.`、`..`、斜线和控制字符。已有完整任务目录或设计文件不再追加后缀。
5. 检查真实路径与符号链接，先解析链接再处理 `..`。追加后的目录必须仍在批准的真实 base 内。遇到碰撞先区分恢复还是新任务，不覆盖。工作区外目录也需要展示真实位置并获得留档许可。
6. 记录原始配置、来源、anchor、解析后的绝对 base 与 `task_dir`。展示用途和范围并取得授权；可写性或配置值不产生授权。写入前再次检查路径、链接和并发变更。

原生配置采用参考插件的 userConfig 方式；不新增项目配置文件，不读取个人秘密配置。目录解析是执行协议，不是完整文件系统沙箱。

## 文档与单一写入负责人

| 路径 | 负责人 | 内容 |
| --- | --- | --- |
| `requirements.md` | Main | 当前确认需求、版本、验收标准与确认依据 |
| `task.md` | Main | 固定目录、模式、身份表、基线、授权与当前调度状态 |
| `development.md` | developer | 当前业务进度、关键决定、阻塞与下一步 |
| `acceptance-developer.md` | developer | 最终整体验收、回归及实操结果 |
| `acceptance-tests.md` | test-developer | TDD 场景映射、组版本、Red 与修订结果 |
| `issues/<id>.md` | developer | 测试问题与补充证据 |
| `issues/<id>-decision-<n>.md` | test-developer | 不覆盖历史的独立裁决 |
| `review.md` | Main | 可选审查 findings 与用户处置 |
| `evidence/developer/`、`evidence/tests/` | 对应角色 | 命令、原始输出、截图、文件标识与范围 |

正文保持简短，不按每次工具调用追加技术流水。状态变化时更新“现在做到哪里”；旧决定需要保留时仅追加关键依据。原始输出使用独立证据文件，不重复复制聊天。证据文件名不能复用覆盖旧结果；不保存秘密和无关个人信息。

机器登记仅保存于宿主实际提供的 `CLAUDE_PLUGIN_DATA/fastdev-v1/`，不把它当业务档案，也不将运行数据提交到插件源码。插件卸载后运行数据可能消失，业务文档仍应独立可读。

## 恢复与角色重建

1. Main 从用户指定的已有任务入口读取固定目录，核对用户真实确认依据、需求版本、模式、基线、用户修改、测试版本及争议裁决。一个 approved 字段不够。
2. 核对实际文件和原始证据；若产物变化，原结果标为失效或待复核，不把历史 PASS 沿用到新代码。
3. 恢复同一角色前先确认未被用户取消、真实 ID 仍有效、工具和返回路由可用。不得只依靠旧 sibling roster 或同名角色。
4. 需要重建时暂停双方写入，Main 启动同角色只读准备，取得新的 Hook 观察身份，再 bind。脚本保留旧 ID 为 retired 并拒绝其编辑。Main 将新身份表同时通知双方，各自用 status 核对；对旧请求返回的迟到结果只存历史，不继续推进。
5. 重建后执行一轮不写代码的直接往返，确认响应回到当前 developer，再放行后续组。消息失败或工具不足就暂停，不把 Main 逐轮代转当默认降级。
6. 登记缺失或损坏时所有 maixdev 写入停止。Main 对照业务档案、实际保护范围和当前宿主身份重建；损坏数据不直接当可信模板。保留旧数据供定位，必要时用新的宿主会话重新 init/bind/登记全部范围，不手改 mode 或删除旧登记来放行。
7. 跨机器路径失效、链接变化或迁移目录需重新确认位置和迁移范围。固定 task_dir 不重算，不因当前配置变化自动移动。

清理只限本任务创建且获准清理的进程、页面和临时资源。取消后不自动重启角色，不删除业务档案或其他任务的运行数据。
