# 验收与证据

成功交付必须满足全部已确认验收项。局部测试通过、结构校验通过、构建成功或历史 PASS 均不能代替最终产物验收。

## 每条验收项

在 [验收模板](../templates/acceptance.md) 中记录业务结果、验证方式、实际结果、证据路径和产物标识。结果只用 `通过 / 失败 / 阻塞 / 未执行`，不能把环境失败写成预期 Red。

测试应说明“哪种错误实现会被发现”。依据需求设计断言，避免照实现生成预期。可在获准的独立临时副本中用错误实现验证测试确实失败；未经授权不改真实工作区、不引入依赖或调用付费服务。没有做反例运行时如实写未执行，不用字符串检查冒充业务行为证明。

## 最终回归

1. 核对需求版本、完整场景映射、保留行为、实际源码和测试配置；包括未提交及未跟踪文件，不只记录 HEAD。
2. 暂停进一步修改，记录最终文件清单与 SHA-256，或使用 guard 的 stamp 绑定完整显式范围。排除缓存/日志只能排除非业务产物，不因此漏掉测试选择配置、数据或快照。
3. 在最终代码上重新执行全部适用测试组及获准回归，保存命令、运行目录、退出码、原始输出与时间（实际读取，不编造）。既有组通过记录仅作为历史，不计入本次最终通过。
4. 检查运行前后产物是否一致，可用 verify-stamp；变化后重跑受影响检查，影响不明时扩大获准回归或交 Main。重新生成指纹不能让旧 PASS 自动恢复有效。
5. TDD 下对照起始基线与测试作者历次交接，复核所有测试、数据、快照、辅助文件和判定配置的变更。检查 Bash/其它工具间接写入、跳过、缩小执行范围、弱化断言及无依据修订。无法确认作者或依据时暂停，不给通过。
6. 自动测试外的验收逐项实操。前端由 developer 亲自使用实际 Chrome DevTools，先 wait，再截图；网络请求和控制台按任务检查。缺浏览器或消息工具就阻塞，不改用模拟证据。
7. 全部验收通过后才返回 complete。用户选择审查及批准修复后，修复仍按原归属执行，并重新验收。

## 本插件离线检查

在可信源码中运行，仅使用 Python 标准库和 TemporaryDirectory，不访问用户真实插件运行数据：

```bash
python3 -I -B plugins/maixdev/tests/test_guard.py
```

命令从市场仓库根运行，或改成脚本绝对路径。覆盖登记、正常/拒绝路径、模式隔离、测试数据与配置、路径别名、角色退休、显式新组漏登记、损坏状态及最终指纹失效。它直接调用 Python 实现和命令入口，不是 Claude Code Hook 的真实调度测试。

`claude plugin validate` 仅作为非模型结构检查。它是否检查每个 Hook 字段必须以实际输出为准，不把整体 Validation passed 当成宿主失败策略或 SendMessage 路由的运行证据。

以下为待执行用例，不是通过记录。安装/加载、模型、预算、隔离 HOME、凭证来源、网络、停止与清理条件必须先获用户授权；不读取个人配置或在现有会话静默激活插件。每例保留 CLI 版本、加载来源、实际事件、工具结果与产物状态，脱敏后存获准证据位置。

| 用例 | 操作与能抓住的错误 | 通过条件 |
| --- | --- | --- |
| H1 入口与配置 | 未确认需求、未选择模式；默认及自定义目录；空值、占位符、切换 cwd、恢复 | 不越过确认门禁；固定目录不漂移；无效配置可见阻塞 |
| H2 身份绑定 | 只读启动两角色，读取真实 SubagentStart 事件，未绑定时尝试受控 Write/Edit；绑定后再试 | 真实 session/type/ID 匹配；绑定前拒绝；test-developer 正常修订 |
| H3 正常直接通信 | developer 请求首组，测试作者返回 Red；实现 Green/Refactor，再请求下一组；触发 need-info | 结果回当前 developer；Main 不逐轮代转；无互等 |
| H4 运行期故障（R1） | 开发开始后，在获准隔离副本分别制造缺脚本、异常退出与超过 10 秒的 Hook；尝试受保护编辑 | 宿主真实阻止编辑，原文件字节未变；记录普通/无关编辑是否也受阻，不能隐藏故障隔离限制 |
| H5 新组漏登记（R1） | 第二组新增外部快照但未 protect，将其列入 handoff_paths；另演练作者完全漏报清单的情形 | 前者 seal/activate 失败，developer 保持暂停；后者由实际 diff 对照发现并补登记，不能宣称脚本自动识别 |

| H7 身份重建（R1） | 暂停后重建 developer 或测试作者，绑定新 ID，发送只读 resume-check 和后续请求，注入旧结果 | 旧 ID 编辑被拒绝；双方改用当前 ID；结果回当前发起方；迟到响应不推进 |
| H8 争议分支 | 给出测试正确、错误/遗漏、信息不足、需求不清四种材料 | 作者独立判断；修订有依据且重新登记运行；需求不清交用户，不弱化测试 |
| H9 隔离与取消 | 两个会话分别 normal/TDD，正常脚本下编辑；损坏/删除 TDD 登记；取消后发送迟到消息 | 普通模式健康编辑不受 TDD 保护；损坏 TDD 阻塞；取消后不复活角色 |
| H10 前端与审查 | developer 实际使用 Chrome DevTools 操作、等候、截图、请求/控制台检查；验收后选择不审查或一个 reviewer | 无工具不冒充验收；审查可选；未经批准不拆分、不修复 |

网站验收单独进行：使用真实 maixdev 市场条目生成 catalog，运行现有采集测试、类型检查和构建；再用 Chrome DevTools 检查卡片、详情、配置默认说明、两个必填敏感 API Key 定义、README、一个 Skill、三个 Agent、Hook、两个 MCP、安装信息、网络和控制台并留截图。网站只展示配置定义和服务名，不显示用户值或认证头；构建不等于网页已实操。

## 检索增量的离线检查

以下命令从市场仓库根执行，使用现有依赖，不安装软件。先生成真实 catalog，再运行结构测试；构建会再次通过现有 prebuild 生成 catalog，不手改生成文件。

```bash
node site/scripts/collect-plugins.ts
node --test plugins/maixdev/tests/test_catalog.mjs plugins/maixdev/tests/test_retrieval.mjs site/scripts/collect-plugins.test.mjs
python3 -I -B plugins/maixdev/tests/test_guard.py
claude plugin validate plugins/maixdev
npm run build
```

检索结构测试检查必填敏感字段、固定服务地址、仅请求头引用配置、受限角色的最小工具集合、四个入口强制读取共享参考，以及角色独占证据与失败规则。它们能发现配置或文本契约被删除、扩大或改错，不能证明 Agent 会遵守规则、凭证已替换或 MCP 已连接。真实服务和行为必须另按以下用例执行。
