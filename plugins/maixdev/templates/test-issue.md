# 测试问题模板

仅发生争议时创建。developer 写 issues/<id>.md；test-developer 写独立的 issues/<id>-decision-<n>.md，不覆盖问题或旧裁决。

## developer 的问题文件

- 问题编号、请求 ID、需求版本与验收项：
- 涉及测试绝对路径、组版本与标识：
- 当前测试要求什么：
- 为什么可能不符业务规则：
- 最小输入、预期业务结果及实际结果：
- 原始证据位置及对应产物：
- 建议与待澄清点：

只陈述证据和建议，不修改测试、不替测试作者裁决。补充证据保留原问题。

## test-developer 的裁决文件

- 对应问题版本、需求依据与实际复核范围：
- 裁决：测试正确／测试错误或遗漏／信息不足／需求不明确：
- 业务理由与最小反例：
- 后续负责人和动作：
- 若修订：改动依据、新版本、运行结果、保护登记 revision、交接证据：
- 若升级：需要 Main 请用户明确什么，哪些工作暂停：

裁决不因实现困难而降低标准；后续发现新证据时新增裁决版本，不抹去原依据。
